# 验证样例

首次使用新浏览器身份或新 API user 时没有档案；证据目录的测试数据不会自动加载。

| 步骤 | 输入或操作 | 应检查的实际行为 |
|---|---|---|
| 1 | 相机在蓝色背包，电池还没充，三脚架借给小张了。 | 分别登记三个物品，保存相机位置、电池待充、小张借用；有真实写入回执 |
| 2 | 我上次把相机放在哪里？ | 显示上次位置，不把历史记录说成当前一定在那里 |
| 3 | 我的相机找不到了 | 开立调查案，建议检查已有位置或追问最后使用场景 |
| 4 | 蓝色背包找过了，没有相机。 | 记录已排查；下一步不继续推荐同一位置 |
| 5 | 昨天换成黑色相机包去拍照了，可能忘在里面。 | 保存为调查线索，不擅自登记当前位置 |
| 6 | 新对话 → 继续办案 | 同一案件 ID、原排查和线索仍在 |
| 7 | 相机找到了，在黑色相机包里。 | 明确结案，保存找到位置，常用位置仍为空 |
| 8 | 现在把相机放在书桌右侧抽屉，以后也固定放这里。 | 分别保存当前位置记录与常用位置 |
| 9 | 明天出去拍照，只核对相机、电池、三脚架，做出门检查。 | 只核对指定物品；电池需充电与装包，三脚架需取回与装包 |
| 10 | 电池充好了，但还没装包。 | 仅充电完成，装包仍待办 |
| 11 | 相机已装包，电池也装包了。 | 两个装包任务都完成 |
| 12 | 相机从包里拿出来了，还没重新装包。 | 相机装包退回待办，电池不受影响 |
| 13 | 相机已经重新装包了。 | 只恢复相机装包完成 |
| 14 | 这次不带三脚架。 | 本次相关事项排除，但三脚架依旧借给小张 |
| 15 | 新对话 → 查看我这次的出门清单，还差什么？ | 保留本次进度 |
| 16 | 后天出去拍照，重新做一份出门检查，只核对相机、电池、三脚架。 | 新清单，各事项重新确认，不继承前一天的打勾 |
| 17 | 相机又找不到了；钥匙也找不到了；新对话 → 继续办案 | 追问具体案件，不混用对象或线索 |
| 18 | 用另一个 API user 查询相机 | 看不到前一个用户的档案 |

自动验收：`python3 scripts/verify_ai_e2e.py --with-outages`。脚本会临时在 Dify 中禁用该模型，再恢复；短暂停止 PowerContext；重建 PowerContext 和记忆桥。故障期间应明确“尚未修改”或“无法读取”，恢复后无故障时的伪造物品，之前的 scope、案件和清单仍保留。

单元测试另外检查：整轮回滚、同轮重试只写一次、写入后超时核对回执、旧版本不能覆盖、借出未取回不能装包、无依据位置不落档，以及多个日期同类活动的选择。单元测试采用内存假的存储，不能代替上述真实端到端验收。
