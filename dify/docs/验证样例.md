# 验证样例：记仇小妖

> 目标：评审按步骤操作，能亲眼看到「小妖记住恶作剧 → 新会话翻旧账」。
> 依赖：PowerContext 已在 `127.0.0.1:18080` 运行，记忆桥已在 `19080` 运行，DSL 已导入并选好模型。

## 0. 初始状态

| 项 | 值 |
|---|---|
| PowerContext Scope | `记仇小妖 · GrudgeImp`（首次启动桥接时自动创建，`backend/.scope.json` 里能看到 `scope_id`） |
| 实测状态 | 已在 Dify 0.15.3 跑通两轮，记忆 9 → 11 条（见 `evidence/05-dify-e2e.json`） |
| 记忆条目 | 0 条（干净状态） |
| Dify 应用 | `记仇小妖 GrudgeImp`，已发布 |

确认命令：

```bash
curl -s http://127.0.0.1:19080/health
# {"ok":true,...,"memories":0}
```

## 1. 用例 A：说一件新坏事（写入 + 回应）

**操作**：在 Dify 应用对话页输入

> 我把你的咖啡换成酱油了，还说是新口味。

**预期表现**：
- 小妖用 1–2 句吐槽回应，语气欠揍（取决于所用模型）；
- 不提及「数据库」「记忆」等实现细节；
- PowerContext 条目数 0 → 1。

**核对**：

```bash
curl -s http://127.0.0.1:19080/health | python3 -m json.tool | grep memories   # "memories": 1
```

## 2. 用例 B：新会话翻旧账（跨会话召回，核心）

**操作**：
1. 在 Dify 右上角**新开一个会话**（或刷新页面重新开始）；
2. 输入

> 你还记得我干过什么吗？

**预期表现**：
- 小妖提到「咖啡换成酱油」这件具体的事；
- 不能编造用例 A 之外的事（此时库里只有这一条）。

**核对**：

```bash
curl -s -X POST http://127.0.0.1:19080/recall \
  -H 'content-type: application/json' \
  -d '{"query":"咖啡 酱油","limit":3}'
# {"memories":[{"text":"我把你的咖啡换成酱油了，还说是新口味。","kind":"prank","score":...}],"count":1}
```

## 3. 用例 C：无关输入不硬编（防幻觉）

**操作**：新会话输入

> 今天天气不错，适合写代码。

**预期表现**：
- 小妖正常接话（可轻微阴阳怪气），**不主动提**咖啡酱油的事，因为与当前输入不相关；
- 若模型仍提及旧账，视为召回过度，属于可调项（降低 `limit` 或改进过滤）。

## 4. 用例 D：多条记忆与排序

**操作**：连续输入三件不同的坏事：

> 1. 我又把你的充电线藏起来了
> 2. 上次说你代码有 bug，其实是夸你
> 3. 我把你的键盘 Ctrl 键换成了 Caps Lock

再问：

> 你最近记了我哪些仇？

**预期表现**：小妖至少能说出其中两件；条目数 4（含用例 A）。

**核对**：

```bash
curl -s http://127.0.0.1:19080/health | python3 -m json.tool | grep memories   # "memories": 4
```

## 5. 重置到初始状态

```bash
# 方式一：换一个新 Scope（保留旧数据，便于对比）
rm backend/.scope.json && pkill -f memory_bridge.py
PC_BASE_URL=http://127.0.0.1:18080 python backend/memory_bridge.py &

# 方式二：清空当前 Scope 的记忆（PowerContext 支持按条目停用/删除时使用对应 API）
```

> 重置后 `memories` 应回到 0；Dify 侧无需重新导入，直接开新会话即可。

## 6. PowerContext 在其中的作用（可核对）

| 动作 | 发生时机 | 对应 API |
|---|---|---|
| 建 Scope | 桥接首次启动 | `POST /v1/scopes` |
| 写记忆 | 每轮对话结束（Dify「记一笔」节点） | `POST /v1/memory/remember` |
| 读记忆 | 每轮对话开始（Dify「召回旧账」节点） | `POST /v1/memory/search` |
| 核对总量 | 任意时刻 | `POST /v1/memory/entries/list` |

原始调用记录见 `evidence/03-powercontext-raw.txt`；桥接的写入/召回记录见 `evidence/02-remember-recall.txt`。

## 7. 失败与边界

| 情况 | 预期行为 |
|---|---|
| 桥接没启动 | Dify 的 HTTP 节点报错，应用返回执行失败；按 README 启动桥接后重试 |
| PowerContext 没启动 | 桥接 `/health` 返回 `ok:false` 与错误信息；Dify 节点报错 |
| 模型不可用 | Dify 报模型调用失败；在应用设置里换模型 |
| 库里没有相关旧账 | 小妖只回应本次输入，不编造 |
