# 验证样例：忘事管理局

前置：全容器栈已启动（见 README §0），DSL 已导入、已发布、已创建 API Key。
初始状态：PowerContext 里记录数可以是任意值，先记下 `/health` 的 `memories` 数字。

## 用例 A：归档

输入：

```
存：备用钥匙在玄关第二个抽屉
```

预期：返回回执「已归档：存：备用钥匙在玄关第二个抽屉」，且 PowerContext 记忆 **+1**。

核对（宿主机）：

```bash
curl -s http://127.0.0.1:19080/health   # memories 比之前大 1
```

## 用例 B：查询（核心）

输入：

```
查：钥匙在哪
```

预期：走 `/recall` 检索到「备用钥匙在玄关第二个抽屉」，模型据此回答（内容取决于所用模型），**不会**凭空编造没登记过的位置。

## 用例 C：兜底

输入：

```
你好
```

预期：返回使用说明（「存：…」「查：…」），不写入记忆。

## 用例 D：跨会话

新开会话再问一次 `查：钥匙`，仍能召回 —— 说明记忆在 PowerContext 而非上下文窗口。

## 失败排查

| 现象 | 检查 |
|---|---|
| 回答「这条没登记过」但确实存过 | 桥的 `/recall` 是否 200；关键词是否被分词命中 |
| 直接报错 / 500 | 模型是否已配置；`memory-bridge` 容器是否在跑 |
| 记忆不增长 | `ssrf_proxy` 是否也能解析 `memory-bridge`（全容器模式天然满足） |
