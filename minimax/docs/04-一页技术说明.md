# 04 一页技术说明

## 模块结构

```
minimax/
├── sdctx/                         上下文模块（Python 包，纯标准库 + pymysql + pylibseekdb）
│   ├── config.py                  全部配置项（环境变量覆盖，零配置可跑）
│   ├── seekdb_store.py            seekdb / OceanBase 接入：嵌入式实例或外部实例，建表 + ngram 全文索引
│   ├── ingest.py                  导入规格 / 代码 / 测试（Markdown 规格解析 + ast 符号解析）
│   ├── retrieve.py                检索：数据库全文检索 + 词项加权打分，两路合并
│   ├── context.py                 组装开发上下文并校验来源真实性
│   ├── state.py                   任务状态：写 PowerContext / 读 PowerContext
│   ├── powercontext_client.py     PowerContext HTTP 客户端
│   ├── minimax_client.py          MiniMax OpenAI 兼容客户端
│   ├── symbols.py                 按符号（ast）定位并整段替换代码
│   ├── patching.py                unified diff 解析与应用（兜底路径）
│   ├── agent.py                   上下文 → MiniMax → 落盘 → 测试 → 回滚重试 的闭环
│   └── cli.py                     命令行入口
├── business_project/              被修改的业务工程（schedule 1.2.2，MIT，见 NOTICE.md）
│   ├── schedule/                  上游源码（修改后）
│   ├── upstream_reference/        修改前快照
│   ├── specs/                     当前生效的规格
│   ├── spec_revisions/            规格的历史版本（v1 / v2）
│   └── tests/                     官方测试 + 本次目标测试 + 既有行为回归
├── tests/test_sdctx.py            上下文模块自身的单元测试
├── scripts/                       安装 / 启动 / 复位 / 一键验证

└── evidence/                      全部运行证据
```

## 上下文选择方式

1. **导入**：`sdctx ingest` 把三类资料写进 seekdb——
   * 规格：Markdown 按 `## R-xxx-xxx` 切成可独立检索的条目，带类型 / 版本元数据；
   * 代码：`ast` 解析出类与函数，记录行号与完整源码；
   * 测试：`ast` 解析出每个 `test*` 函数。
2. **检索**（`sdctx/retrieve.py`，全部在数据库内完成）：
   * 全文路：`MATCH(title, content) AGAINST (<任务描述> IN BOOLEAN MODE)`，ngram 分词，中文可用；
   * 词项路：任务描述 → 英文标识符 + 中文二元组 → `CASE WHEN ... LIKE ... THEN n END` 加权计分；
   * 两路按 id 合并排序取 top-k。
3. **选择可编辑符号**：命中类时展开出它的全部方法，并剔除"只是前缀"的粗粒度符号
   （例如有 `Scheduler.run_pending` 就不再暴露整个 `Scheduler`），
   避免模型整类替换导致无关改动。
4. **组装与校验**：输出规格条目 / 代码符号 / 测试用例，每条都带路径、行号、`sha256`，
   并回磁盘校验 `source_exists`。
5. **拼接任务状态**：从 PowerContext 读回"已完成 / 待办 / 已有验证结果"，一起写进提示词。

## 各项技术的分工

| 技术 | 承担的角色 | 具体做什么 | 不承担什么 |
| --- | --- | --- | --- |
| **seekdb / OceanBase** | 工程资料与索引的存储 + 检索 | 保存规格条目、代码符号、测试用例；建 ngram 全文索引；执行检索 SQL | 不保存任务状态，不参与代码生成 |
| **MiniMax** | 代码生成与修改 | 读取开发上下文，产出**落到真实文件里**的符号替换块 | 不做检索，不做状态管理 |
| **PowerContext** | 任务状态的持久化与复用 | 写入 Source 日志（完整状态）与 Atomic Memory（进展摘要）；重启后读回并注入上下文 | 不存工程资料，不生成代码 |

## 一次完整任务的时间线

```
 规格/代码/测试 ──ingest──> seekdb
                            │
                     retrieve（两路 SQL）
                            │
                     context（校验来源 + 读 PowerContext 状态）
                            │
              ┌─────────────┴──────────────┐
        写入状态到 PowerContext        提示词 ──> MiniMax
              │                              │
              │                        符号替换块
              │                              │
              │                    ast 定位 → 整段替换 → 编译校验
              │                              │
              │                        跑测试 ──失败──> 回滚 + 失败信息回灌模型
              │                              │
              │                         通过 → 保留
              │                              │
              └──────────> 保存新状态 ◄──────┘
```

## 关键设计取舍

| 取舍 | 原因 |
| --- | --- |
| 用「符号替换」而不是让模型写 unified diff | 模型给出的上下文行与行号经常和真实文件不一致；按 `ast` 定位符号再整段替换，改动一定落在真实代码上，也不会误伤文件其他部分 |
| 替换块按相对缩进整体平移 | 模型常把方法体按顶层缩进给出，整体平移可以保证落到文件里仍是合法类成员 |
| 落盘后立刻跑测试，失败就回滚并回灌 | 让"规格 → 代码 → 验证"形成闭环；模型的错误不会留在仓库里 |
| 状态分 Source + Memory 两层 | Source 存完整快照（不可覆盖，用修订号递增）；Memory 存可检索摘要，方便"先回忆上次进展" |
| 检索全部下推到数据库 | 规格是中文，ngram 全文索引直接可用；词项打分也在 SQL 里完成，保证"查询结果真正用于构造上下文" |

## 已知限制

* 嵌入式 seekdb 的数据目录不能被多个进程同时打开，本模块按"一次一个进程"使用。
* MiniMax-M3 推理开销较大，单次改动 25–120 秒；推理耗尽 token 预算时可能来不及给出补丁。
* 上下文质量取决于规格与测试的写法；规格条目越具体，检索命中越准。
* 当前只支持单仓库（一个业务工程）；多仓库需要把 `ctx_document.path` 扩展成带仓库前缀的路径。
