## 1. 业务工程

| 项 | 值 |
| --- | --- |
| 工程 | `schedule` 1.2.2（Python 任务调度库，MIT 许可） |
| 来源 | PyPI 官方发布包 `schedule-1.2.2.tar.gz`，见 `business_project/NOTICE.md` |
| 位置 | `business_project/schedule/`（源码）、`business_project/tests/`（测试） |
| 运行方式 | `cd business_project && python -m pytest tests/ -v` |
| 修改前快照 | `business_project/upstream_reference/schedule__init__v1.2.2.py` |

既有行为有明确的规格基线，适合验证"新增能力不破坏原有行为"。

## 2. 任务描述

> 让 `Scheduler.run_pending` 隔离单个任务异常：失败任务调用 `on_error` 回调，且不影响同轮其他任务。

## 4. 要改什么（SPEC-003 v1）

规格全文见 `business_project/specs/SPEC-003-job-error-isolation.md`，条目摘要：

| 条目 | 要求 |
| --- | --- |
| R-003-001 | `run_pending()` 中某个任务抛异常，不得中断同一轮其余到期任务 |
| R-003-002 | 异常交给 `on_error(job, exception)` 回调；未配置回调时记录 `warning` 日志且不再抛出 |
| R-003-003 | `Scheduler.on_error` 属性默认 `None`，构造后可赋值 |
| R-003-004 | `run_all()` 同样隔离异常 |

## 5. 哪些原有行为必须保持（SPEC-001 / SPEC-002）

| 条目 | 要求 | 守护测试 |
| --- | --- | --- |
| R-001-001 | `run_pending()` 不补跑错过的周期 | `test_missed_jobs_are_not_repeated`、官方 `test_run_pending` |
| R-001-002 | 到期任务按 `next_run` 升序执行 | `test_due_jobs_run_in_next_run_order` |
| R-001-003 | 返回 `CancelJob` 的任务被取消 | `test_cancel_job_behaviour_is_preserved` |
| R-001-005 | `get_jobs(tag=...)` 按标签筛选 | `test_tag_filtering_is_preserved`、官方 `test_tagging` |
| R-002-001 | `next_run` 取最早任务 | 官方 `test_next_run_time_*` |
| R-002-002 | `idle_seconds` 计算 | 官方 `test_idle_seconds` |

此外，`business_project/tests/test_schedule_upstream.py` 是 schedule 1.2.2 的**原样**官方测试，
81 个用例全部必须通过。
